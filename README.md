# AION Workshop 3.1.0

Локальна майстерня AION 2: порівняння крафту, закупівля ресурсів, переробка ефіру та історія ринку. Інтерфейс українською, предмети російською або англійською.

**[Завантажити AION-Workshop.exe](https://github.com/MrM0y/aion-workshop/releases/latest/download/AION-Workshop.exe)** · [Усі релізи](https://github.com/MrM0y/aion-workshop/releases) · [Відгуки](https://github.com/MrM0y/aion-workshop/issues)

## Запуск

Завантаж один EXE й запусти. Потрібна Windows 10/11 x64. Node.js уже всередині. Перший запуск розпаковує програму в одну службову папку `%LOCALAPPDATA%\AIONWorkshop`, відкриває браузер і залишає значок біля годинника. Через цей значок можна знову відкрити програму, перевірити оновлення або завершити роботу. У папці завантажень не з’являються тисячі файлів. Усі внутрішні ресурси та окремі дані користувача знаходяться у службовій папці.

При кожному запуску launcher перевіряє новий реліз на GitHub. Якщо він є, пропонує оновити. Завантаження перевіряється за SHA256, нова версія встановлюється окремо; налаштування та історія залишаються в `data`. Якщо мережі немає, запускається встановлена версія. Якщо нова версія не стартує, launcher повертає попередню. Збірка поки не має платного цифрового підпису видавця.

## Відгук просто з програми

Натисни **Відгук** унизу праворуч → вибери місце → напиши пропозицію. Програма додає екран, рецепт, версію та позначений елемент. На GitHub переглянь нотатку й підтвердь створення Issue зі свого облікового запису. Власник отримує GitHub-сповіщення. Зображення екрана та особистий стан не надсилаються автоматично; скриншот можна додати на GitHub за бажанням. Для дуже довгого тексту програма запропонує скопіювати його повністю.

Офіційний код змінює власник; відвідувачам не видаються права запису. [Як залишити відгук](CONTRIBUTING.md).

Збірка EXE на Windows: `powershell -NoProfile -File scripts/build-release.ps1 -Repository MrM0y/aion-workshop`. ## Межі даних і попередні зміни

## Що нового

**Збір із гри → Вибрати вікно гри → AION2.** Поки видно ринок, програма раз на 12 секунд читає повні видимі лоти, кількості та податок через Windows OCR. Перемикання предмета у грі підхоплюється автоматично. Кадри обробляються локально та видаляються; гра не керується. Браузер просить вибрати вікно заново після перезапуску. Потрібні Windows 10/11 і компоненти OCR мови гри. Якщо вікно згорнуто або ринок закрито, повної книги інших предметів отримати неможливо.

Новіші автоматичні ціни мають пріоритет над старими ручними. Невдалий або порожній запит не стирає ще свіжі прочитані лоти. Книга з екрана часткова: використовуються тільки розпізнані одиниці, без вигаданого продовження. Знімки старші години не підтверджують поточну закупівлю. Імпорт скриншота зберігає час файла.

У всіх звичайних рецептах перевіряється виготовлення проміжних ресурсів, зокрема з ефіру. Закупівля враховує цілі партії, залишки, спільні ресурси та дорожчі лоти. Пошук обмежений за часом: це найкращий перевірений варіант, не доказ глобального оптимуму. Для спорядження автоматична заміна обмежена детермінованими маршрутами без округлення виходу; непідтверджений випадковий допоміжний крафт не видається за точний ризик.

Рецепти переробки з невідомою платою та відповідність прив’язаних матеріалів — **орієнтовний сценарій**. У налаштуваннях можна вимкнути переробки або припущення про нульову плату. Каталог не підтверджує повну взаємозамінність усіх прив’язаних предметів.

У рецепті є оцінка продажу за годину, добу й тиждень за власними підтвердженими лотами тієї самої ціни та кількості. Мінімум — 20 зіставних спостережень з відомим результатом; показується статистичний інтервал. Скасування, зникнення оголошення й час роботи програми не доводять продаж. Повідомлення без точного часу або однозначного лота потребують уточнення й не входять у прогноз автоматично. Формат торгових повідомлень гри ще потребує перевірки на реальних прикладах; накопиченої історії угод у збірці немає. Загальний попит усього сервера з власної вибірки не гарантується. Деталі та формат журналу — у AUTOMATION.md.

Локальний помічник AION 2: рейтинг вигідного крафту й окремий розрахунок спорядження. Інтерфейс український, назви предметів перемикаються між російською та англійською.

## Запуск і передача іншому гравцю

Потрібен Node.js 22 або новіший. Розпакуй папку й відкрий `Start.cmd`; або запусти `node server.mjs`. Адреса: http://127.0.0.1:4173. Сервер працює лише на цьому комп’ютері. Додаткові пакети й npm install не потрібні.

Для передачі використовуй чистий архів або копію папки без `data/state.json`, резервних копій стану й власних налаштувань. Node.js потрібен і на іншому комп’ютері. Публічні джерела не потребують входу чи паролів.

## Як користуватися

1. Під час першого запуску вибери регіон, фракцію та сервер. Вибір запам’ятовується.
2. Натисни **Знайти вигідне**. Програма завантажує всі сторінки спостереженого ринку й зіставляє ціни з рецептами гри. Таблиця показує витрати, очікуваний чистий прибуток і дохідність за одну спробу.
3. Натисни поле пошуку: з’явиться каталог **професія → категорія → предмет** зі справжніми іконками. Наприклад, **Алхімія → Зілля**. Можна одразу писати назву російською або англійською й вибрати підказку. Відсортуй за відсотком прибутку, вкладеннями, прибутком, ризиком збитку за 10 спроб або кількістю продажів у рухомому вікні 28 днів. Можна шукати предмет і обмежити бюджет.
4. Натисни рядок: побачиш справжні матеріали, кількості й можливі результати. Ціни можна виправляти з гри. Порожнє поле видаляє ручну ціну й повертає ціну джерела. Ручна ціна має пріоритет до її видалення.
5. Графіки ціни й попиту видно одразу під прибутком. Періоди: 24 години, 7 і 30 днів. Є поточні цінові рівні, їх кількості та зважене середнє, коли джерело справді їх надало. Для неповного знімка середнє стосується лише зібраних рівнів. Позначки початку й кінця поставки вводяться з гри та зберігаються локально. Відкритий рецепт оновлюється раз на хвилину, якщо вкладка видима й ти не редагуєш його поля.
6. У **Спорядженні** вибери предмет через такий самий каталог, діапазон початку, кількість і ймовірність, що підготовлених грошей вистачить. Натисни **Розрахувати**. Загальна середня сума й бюджет з обраною ймовірністю видимі над компактними плитками. У кожній плитці є запаси, середня кількість для докупівлі, ціна та сума. Початок із готової зеленої чи синьої речі дозволяє купити її або врахувати свої запаси; нестача докуповується. Вже створена біла річ не вважається довільним інгредієнтом, якщо реальний рецепт її не споживає.

Довільних рецептів немає: використовуються ідентифікатори та склади рецептів гри. Старі записи попередньої версії зберігаються у файлі, але редактор власних рецептів і старий майстер підказок більше не відкриваються.

## Що означають розрахунки

Звичайний крафт: усі матеріали купуються. Виручка зважується за ймовірностями звичайного й особливого результатів. Особливий результат замінює звичайний. Невдачі споживають матеріали. Податки віднімаються з виручки; повторне виставлення та непроданий залишок не моделюються.

Спорядження: шанс потрібного особливого результату = успіх базового крафту × активація комбо (зазвичай 25%) × успіх комбо. Останній шанс береться окремо з таблиць джерела за рівнем ремесла. Це не просто 25% на кожному етапі. Ланцюг складається з реальних залежностей; якщо початковий предмет неможливо виготовити за доступним рецептом, він оцінюється як купівля з відповідним поясненням.

Середні витрати без запасів обчислюються аналітично. За наявності проміжних речей використовуються 30 000 відтворюваних симуляцій повного ланцюга. Запаси віднімаються в кожній симуляції від випадкового попиту, а не просто від його середнього. Бюджет — оцінка квантиля; для одного етапу застосовується точний негативно-біноміальний квантиль. За випадкового шансу скінченного бюджету зі 100% гарантією немає.

Матеріали в деталях — середні кількості, а не гарантований набір на обраний відсоток випадків. Бюджет припускає незмінні ціни й можливість докуповувати матеріали під час крафту. Наявні речі не потребують нових грошей, але мають економічну вартість. Орієнтир продажу рахується окремо за повним ланцюгом із нуля, щоб випадкова удача не занижувала оцінку.

## Дані та їхні межі

- [Aion2.app](https://aion2.app/crafting): 760 рецептів (322 craft, 190 succession, 248 conversion), 9 334 предмети в об’єднаному EN/RU каталозі, 9 322 завантажені іконки. Для 12 предметів джерело не повернуло справжнього зображення. Російські назви надані джерелом; офіційність цієї локалізації не підтверджена.
- [Metabot](https://metabot.gg/en/aion-2/crafting): таблиці шансів за рівнем ремесла. Рецепти зіставляються за ID, продуктом і потрібним рівнем; непідтверджені шанси не вигадуються.
- [Aion2Market](https://aion2.exchange/): найнижчі спостережені ціни оголошень, їх історія та агрегати продажів. Програма показує справжній час спостереження. Повторне завантаження не робить старий знімок новим. Покриття обмежене тим, що бачить джерело; товарів без поточних оголошень може не бути в розрахунку.
- Ціни NPC — [довідник TW](https://github.com/xtopolis/aion2-static/blob/main/src/data/vendor-prices.json), записаний 19.08.2026. Вони явно позначені як довідкові й потребують звірки для іншого регіону; їх можна виправити вручну.
- Точна комісія кожного сервера не підтверджена публічним джерелом. Для нового ринку використовується явно позначене припущення 10%; збережена користувачем ставка не змінюється. Комісії та рівень ремесла доступні через **Налаштування**. Це не блокувальне опитування. У налаштуваннях можна вимкнути врахування невдалих спроб: оптимістичний сценарій явно позначається, а шанс активації комбо зберігається. Орієнтир повної собівартості спорядження для продажу завжди враховує фактичні невдачі.
- Рейтинг не доводить, що товар продасться за поточну ціну. Джерело не дає надійного прогнозу часу продажу, шансу купівлі за 1–3 дні чи розкладу термінових поставок. Підсумки за 28 днів не видаються за продажі за день.

Походження, час завантаження та помилки зображень записані у `public/data/catalog-sources.json`. Для повторного завантаження каталогу: `npm run sync:catalog -- --refresh`. Без --refresh використовуються локальні кешовані відповіді. Потрібен інтернет, операція завантажує багато зображень.

## Збереження та перевірки

Стан зберігається у `data/state.json` атомарним записом і в localStorage браузера. Для одного ринку зберігаються свої ціни й комісії. Пошкоджена копія не стає порожнім станом мовчки. Вибирається новіша коректна копія за savedAt.

Перевірки: `npm test` і `npm run check`. Фронтенд не має сторонніх залежностей. Локальний API приймає записи лише зі свого Origin; зовнішні маршрути обмежені дозволеним переліком.

## Історія й оцінка часу продажу

Історія накопичується окремо в `data/state.json.history/`, по серверу та ID предмета. Вона підтягується при відкритті графіка й його оновленнях; фоновий збір усіх предметів при закритій програмі не запускається. Оригінальний час спостереження зберігається. Межі: 730 днів, до 30 000 цінових точок, 1 200 спостережень продажів і 500 позначок поставок на предмет.

Коли є статистика продажів, графік показує її 28-денні рухомі підсумки. Якщо її немає, відображається **пропозиція — кількість оголошень**, з чіткою відповідною назвою. Дельти рухомих підсумків не прирівнюються до продажів за день. Зникнення оголошень не прирівнюється до угод.

Умовна оцінка черги доступна лише за свіжих повних цінових рівнів і придатної серверної статистики з підтвердженим 28-денним вікном. Формула: `(товар дешевше або за тією самою ціною + твоя партія) / історичний середній потік за день`. Усі припущення видно в **Як оцінюється час**. Це сценарій, не калібрований прогноз фактичного продажу й не ймовірність. Для каррі на Nemon перевірене джерело не мало ні статистики продажів, ні глибини, тому хвилини не вигадуються.

Типовий низ за останню добу — медіана спостережених найнижчих оголошень. Частка спостережень, де низ був не нижче твоєї ціни, — історичний орієнтир ціни, не шанс продажу. При виборі ціни з орієнтирів очікуваний прибуток перераховується одразу.

Детальне дослідження KR/TW/Global джерел і математичних обмежень: **SOURCE-RESEARCH.md**. Публічний контракт провайдера: https://aion2.exchange/api/openapi.json . Корейські ціни AEID не змішуються з даними Global Nemon.

При великих розривах цін графік автоматично використовує явно позначену логарифмічну шкалу, щоб були видимі й менші зміни; числові ціни не змінюються.

## Нове у 2.2

Один графік зі спільним часом: ціна зліва у Kinah, обраний кількісний шар справа. Галочками вмикаються ціна, пропозиції або продажі за28днів, своя ціна, середнє та поставки. Пропозиції й продажі не накладаються одночасно на одну вісь через різні одиниці. Є6–8 підписів часу, zoom+/−, повернення до всього періоду, перетягування графіка, Ctrl+колесо та два повзунки меж. При наближенні до хвилин підписи містять секунди. Кожна підказка показує справжній час свого спостереження; годинних продажів із28-денних підсумків не вигадано. «Уся збережена історія» відкриває накопичені локальні точки; нова зовнішня історія обмежена можливостями провайдера.

У рецепті замість множення найнижчої ціни на всю партію є **Знайти вигідну закупівлю**. Вкажи кількість спроб або бюджет. Програма використовує дешевші одиниці першими, а після вичерпання переходить до дорожчих. У таблиці одразу видно кількість і кожний використаний ціновий рівень: «3 шт. × 3500». Бюджет обмежує матеріали+крафт; можливі авансові комісії виставлення треба мати окремо, усі комісії віднімаються з прогнозованого прибутку.

Якщо у джерела немає кількостей, відкрий **Змінити лоти** матеріалу. У кожному рядку введи ціну за штуку й доступну кількість; кнопка **+ Наступна ціна** додає ще один рівень. **Зберегти й підібрати** одразу перераховує закупівлю. Ручний знімок діє лише у відомому обсязі й має позначку ручних даних. Одна ручна ціна за штуку не підтверджує необмежену кількість. Для навмисної приблизної оцінки є окремий вимкнений за замовчуванням режим; такі результати явно позначаються. Налаштування закупівлі рецепта й ручні лоти запам’ятовуються для цього сервера.

Бюджет у головному пошуку перемикає всі суми на **всю партію**. Кожен рядок є окремим варіантом використання бюджету, а не частиною спільного портфеля. Алгоритм обирає максимум очікуваного прибутку, тому іноді вигідніше витратити лише частину грошей або не крафтити. Майбутня виручка повторно не вкладається в цій закупівлі. Невідомі кількості не замінюються необмеженою нижньою ціною. Рецепти без достатніх кількостей показуються окремо й враховують пошуковий фільтр.

Сортування за вкладенням, прибутком і дохідністю доступне натисканням заголовків колонок: повторне натискання міняє напрямок. Є також кількість спроб, опублікований оборот і ризик. Для партій понад50спроб точний ризик у цій моделі невідомий; він не підміняється старим ризиком10спроб. Невідомі числа сортуються останніми в обох напрямках.

Межі закупівлі: давність цінових рівнів до1години, невідоме право часткової купівлі стеків, можлива зміна лотів до покупки, довідкові NPC-ціни. Продаж усіх результатів за заданою ціною залишається проєкцією. Критичні інваріанти та перевірки: REVIEW.md.

У бюджетному режимі дохідність таблиці = очікуваний чистий прибуток / гроші на закупівлю й крафт. Імовірнісний розрахунок спорядження поки використовує сталі ціни, як прямо зазначено в його блоці; нова закупівля за ціновими рівнями стосується партій звичайних рецептів.

## Рух ринку · 2.2.1

Кнопка **Перевірити рух за добу** запитує одну свіжу відповідь цінової історії за24години й показує спостережені спади/підйоми кількості оголошень та зміну ціни між знімками. Приклад результату: «↓1 ↑18оголошень · ціна−21,1%». Числа не називаються покупками або унікальними товарами: оголошення могли продати, скасувати або перевиставити.

Не використовуємо для цієї формули змішану локальну історію різних bucket. Пропущений/null count не є нулем; переходи через розриви понад3години не враховуються. У підказці результату є використаний період і покриття. Без двох придатних спостережень кнопка повертає короткий статус. Це не рейтинг попиту й не прогноз продажу.

Шари без даних приховані. Блок часу продажу показується лише коли модель має придатні дані. Кожна доступна галочка керує реальним шаром.

## Вигідні лоти · 2.3.0

Відкриття рецепта автоматично перевіряє кількості. Задай **Не більше спроб** або бюджет. Обидва режими підбирають максимум очікуваного прибутку: можна зупинитися раніше заданої кількості й залишити частину бюджету невитраченою.

Результат показує конкретні лоти й команду «Купи вказані лоти → зроби N спроб». Наступна збиткова спроба, вичерпаний бюджет, досягнута межа та нестача підтверджених кількостей розрізняються. Межа вигідності оцінюється для повного набору матеріалів з усіма комісіями, а не для одного інгредієнта окремо. Усі підсумки стосуються обраної партії. До перевірки кількостей підсумки приховані; найнижча ціна не множиться на невідомий обсяг.

## Спорядження й продажі · 2.4.0

Спорядження: плитки переносяться на наступний рядок. Поле **Уже маю** дозволяє врахувати і готові речі, і сировину. Введена кількість враховується навіть при негайному натисканні **Розрахувати**. Вгорі видно загальні середні витрати та скільки підготувати, щоб грошей вистачило, наприклад, приблизно у 99 зі 100 випадків. Непідтверджені шанси не перетворюються на вигадану суму.

Рейтинг: **Прибуток, якщо продаси**, **% якщо продаси** й окрема колонка **Продажі · 28 днів**. Без свіжого підтвердження угод позитивні суми мають нейтральне оформлення. Фільтр **Є продажі всіх результатів** враховує окремо звичайний та особливий результат. Однакові ID не дублюють продажі; різні періоди не підсумовуються. У рецепті видно зафіксовану середню ціну угод і попередження, коли очікуваний вихід партії більший за весь спостережений 28-денний обсяг.

Свіжість статистики для фільтра — до 36 годин від її спостереження, з урахуванням щоденного оновлення джерела; HTTP-завантаження не оновлює цю дату. Це перевірка наявності недавніх даних, а не гарантія попиту. Середнього строку продажу bulk API не дає: він залишається невідомим. Ризик крафту описує випадкові результати за умови продажу за обраною ціною; він не включає непроданий товар.

## Автоперевірка · 2.5.0 (історія)

Лоти завантажуються після відкриття рецепта й оновлюються щохвилини у видимій вкладці, якщо ти не редагуєш поля. При відсутності даних головна дія — **Перевірити ще раз**; ручний редактор доступний лише як **Виправити вручну**, для NPC його прибрано. Біля ціни матеріалу й продажу є +100, +200, +500, +1000.

Рейтинг автоматично уточнює детальну /volume-статистику для видимих результатів (два запити паралельно, повторна перевірка не частіше п’яти хвилин на предмет/сервер). Одна остання rolling-статистика не підсумовується з іншими. Добове середнє видно лише за підтвердженого свіжого 28-денного періоду; воно не видається за поточний попит чи шанс продажу. Умовна черга, коли для неї є справжні дані, враховує очікуваний вихід всієї партії.

Основний екран щохвилини перевіряє легкий /health; новий знімок викликає оновлення ринку. Форма редагування й невидима вкладка це оновлення призупиняють. Час старих спостережень не замінюється часом запиту.

У релізі 2.5.0 OCR-збирача ще не було. Версія 3.0.0 додає локальне зчитування видимих лотів; межі автоматизації описані на початку документа та в AUTOMATION.md.
